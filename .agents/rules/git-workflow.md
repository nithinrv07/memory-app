# Git Commit & Push Rule

Whenever updates are made to the codebase (features, bug fixes, refactoring, dependencies), always commit and push the changes to GitHub with a descriptive, structured, and conventional commit message (e.g. `feat(...)`, `fix(...)`, `refactor(...)`).
Ensure secrets (such as `.env` files and raw API keys) and build artifacts are kept out of version control and properly git-ignored before committing.
